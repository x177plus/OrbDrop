# OrbDrop 功能型悬浮球设计（提案）

> 版本：v0.1（2026-09-20）
> 状态：**方向已定、细节待评审**（未并入 `requirements.md`；对外无实现承诺）
> 前置：`docs/requirements.md` 3.1 / 3.3 / 3.5（F-01~F-09、F-20~F-25、F-46）

## 1. 要解决的问题

现有悬浮球（`src/lib/components/Orb.svelte` + `src/App.svelte`）只有一个身份：**入口 + 拖入靶**。

- 62px 球，装在 90×90 的置顶窗口里（`COLLAPSED`）
- 单击 = 展开面板；按住拖动 = 移动窗口；贴边 = 收起半颗、悬停滑回
- 拖入（Explorer → 球）= 登记共享项并广播（F-20/F-21）
- **拖出只存在于面板内部**（F-46，`drag.rs` 的 OLE `DoDragDrop`），球本身不能拖出

目标：把球升级成**功能型悬浮球**——球上直接可见"装了什么"（本机 + 各设备的共享项），
并且**能从球上直接把条目拖出到 Explorer/Finder**；拖入语义不变。

### 1.1 真正的难点：一个球，三种手势

球上要同时容纳：

| 手势 | 冲突点 |
|---|---|
| 单击 → 开面板 | 与拖动靠位移阈值区分（已实现，`DRAG_THRESHOLD_PX = 4`）|
| 拖动球体 → 移动窗口 | **与"从球上拖出条目"直接冲突**——同一个按下-拖动动作，两种意图 |
| 拖动条目 → 拖出文件 | 同上 |
| 拖入 → 登记 | 与拖出方向相反，不冲突 |

结论：**冲突的根因是把"拖出"挂在球体本身上**。只要拖出源不是球体，冲突就消失了，
不需要长按/修饰键去猜意图。

## 2. 核心决策

### 决策 A（选定）：「球体 = 移窗，条目片 = 拖出」

- **球体**保持现有全部语义：单击开面板、拖动移窗。
- **拖出源 = 球周展开的条目片（chip）**，每片独立是 OLE 拖出源，复用 `drag.rs`。
- 移动悬浮球的问题**自动消解**——球的拖动从未被占用，无需"移动模式"、无需长按。

为什么不用"长按移窗 / 短拖拖出"：两种意图靠时间去猜，误触成本高（想移窗却拖出一份文件、
或想拖出却把球挪走），而且现有 `Orb.svelte` 的拖拽状态机要推倒重写。**能靠空间区分就不靠时间区分。**

### 决策 B（选定）：hover 展开成「环形条目盘」（bloom），平时仍是 62px 球

"在球里显示目录/文件"在 62px 内无法成立。做法：**悬停时球长成一张条目盘**，
球心仍是球（点=面板、拖=移窗），四周一圈 chip。

- 平时：62px 球 + 两枚角标（左上橙=通知数、右上绿=长连接数）不变。
- 球体内部加一个**容量指示**（装入项数）；这是"球里装了东西"的最小可见信号。
- 悬停 120ms 无按下 → bloom；指针离开 → 收回。`prefers-reduced-motion` 下动效归零（沿用 `MOTION`）。

### 决策 C（选定）：环形按来源分段、以颜色区分

单环，chip 按来源**聚簇成弧段**，段间留缝：

- **本机段**：本机全部共享项（主色蓝）
- **每台长连接设备一段**：该设备对本机可见的共享项（设备色 = 设备标签页同色）
- 离线/未连接设备**不进环**（其共享项对本机本来就不可见）；设备名仍只在面板标签页里看

一眼可分"本机 vs 谁的"，且实现简单（一个环 + 每片一个颜色 + 排序规则）。

### 决策 D（提议，需确认）：拖入的**落点**决定语义

- 拖到**球心** → 登记为本机共享项（现有行为，F-20）
- 拖到**某设备的弧段** → 直接**推送给该设备**（复用 F-50 推送链路）

把"拖入可见"和"推送"合并到一个手势里。这是加分项、非必需，见 §11 待定。

### 备选模型（不选，留档）

| 模型 | 移窗 | 拖出 | 结论 |
|---|---|---|---|
| 乙：球体=拖出当前选中项 | 长按 450ms 进移动模式 | 直接拖球 | 需要"当前选中项"这个概念，而收起态没有选中项；且靠时间猜意图。**不选** |
| 丙：球体固定不可移（只贴边） | 取消移窗，仅四角吸附 | 拖球 | 剥夺现有 F-01「可拖动位置」。**不选** |

## 3. 形态与状态机

```
                 hover(120ms)            pointerleave / Esc
   ┌────────┐  ─────────────────▶  ┌──────────┐  ◀─────────────────  ┌────────┐
   │  idle  │                       │  bloom   │                      │  idle  │
   │ 62px球 │  ◀─────────────────   │ 条目盘   │                       └────────┘
   └────────┘      pointerleave    └──────────┘
     │  ▲                              │   ▲
     │  │ 单击(球心)                   │   │ 单击(球心) / Esc
     ▼  │                              ▼   │
   ┌─────────┐                     ┌─────────┐
   │  open   │  ── 收起 ──▶ idle   │  open   │
   │  面板   │                     └─────────┘
   └─────────┘

   idle/bloom 期间：
     drag-over(外部文件悬停)  → dragIn 态：球高亮放大；bloom 时若悬停设备弧段则该段高亮
     pointerdown(chip) + 位移  → dragOut 态：OLE 拖出中（拖影由 OS 画，其余片淡出到 40%）
```

| 状态 | 视觉 | 退出 |
|---|---|---|
| `idle` | 62px 球 + 容量指示 + 两枚角标 | hover→bloom；click→open；拖入→dragIn |
| `bloom` | 条目盘（球心 + 一圈 chip） | pointerleave→idle；click 球心→open；chip 拖出→dragOut |
| `dragIn` | 球/目标弧段高亮放大（沿用 `.orb-stage.drag` 语言） | 落下→登记或推送；拖出窗口→回上一态 |
| `dragOut` | 被拖片原位半透明，其余片淡出 | 拖放结束→回 bloom |
| `open` | 现有面板 | 收起→idle |

## 4. 条目盘（bloom）布局与视觉

- **盘的尺寸**：直径 `BLOOM_D = 168`（CSS px）；窗口随之从 90×90 长到 `BLOOM_D + 阴影余量`
  （复用 `PANEL_SLACK` 思路）。**窗口围绕球心生长，球心屏幕坐标不动**（否则球会跳）。
- **几何**：球心圆 `r = 31`（球本身，`ORB_SIZE/2`）；chip 环半径 `r ≈ 62`；chip 尺寸 44×44、圆角 12、
  相邻 chip 间距 6；chip 内 = 类型图标 + 截断名（≤6 字符），hover 在盘边弹全名 tooltip。
- **命中**：整盘是一个 `border-radius:50%` 的元素，指针在盘内时用**极角**判定落在哪一片
  （角度→索引）。这样盘内**没有穿透死区**（比离散圆点好）；窗口四角的透明区是仅剩的死区，
  bloom 只活在指针停留期间，可接受。
- **分段与顺序**：本机段在最上（12:00 起），顺时针依次各设备段；段间缝 ≥ 2×chip 间距。
- **颜色**：本机 = `--accent`（蓝）；设备 = 设备色（与设备标签页色一致，由设备名哈希生成）。
  色带画在 chip 外缘一圈，不占图标区。
- **溢出**：每段上限——本机 5 片、每设备 3 片、全场 ≤ 10 片。超限时该段最后一片变成
  `+N` 片（点击 → 展开面板并定位到该来源的标签页）。
- **空态**：无任何共享项时，盘显示一圈虚线 + 中心文案「拖入文件或文件夹」。
- **角标**：bloom 时两枚角标淡出（避免与 chip 抢位）；收回后复位。

## 5. 手势消歧总表

| 指针动作 | 命中 | 结果 |
|---|---|---|
| 单击（位移 ≤4px） | 球心 | 展开/收起面板 |
| 拖动（位移 >4px） | 球心 | **移动窗口**（现有 `beginOrbDrag`） |
| 右键 | 球心 | 上下文菜单（移动位置提示 / 贴边 / 隐藏 / 设置 / 退出） |
| 单击 | chip | 展开面板并定位到该项（选中态） |
| 拖动（位移 >4px） | chip | **原生拖出**（本机项 `CF_HDROP`；对端项虚拟文件，复用 `drag.rs`） |
| 外部文件悬停 | 球心 | 高亮 → 落下 = 登记共享项（F-20） |
| 外部文件悬停 | 设备弧段 | 高亮该段 → 落下 = 推送该设备（决策 D） |
| 拖动中悬停（拖着文件过来） | 球 | 立即 bloom（不等 120ms），供进一步定位 |

**键盘/无障碍**：chip 可 Tab 聚焦；Enter = 打开面板定位；球体保留现有 Enter/Space = 开面板。

## 6. 贴边 / 角标 / 多显示器兼容

- **贴边态 bloom**：先按现有 hover 滑回逻辑把球滑到完整可见位，再展开盘；指针离开先收盘、
  再回贴边。滑回期间禁止起拖（复用 `Orb.svelte` 的 `isSliding()` 判据）。
- **窗口尺寸切换**：bloom 的窗口放大必须等 WebView2 视口跟上（复用 `waitForViewport` 补丁），
  否则盘先以窄宽出现再跳宽。
- **多显示器 / DPI**：盘的物理像素换算走现有 `orbScreenMetrics`；窗口生长时要 clamp 在工作区内，
  靠边时盘向屏幕内侧生长（不影响球心锚定）。
- **面板打开时**：球和盘整体隐藏（现有 `.open` 行为不变）。

## 7. 数据与排序规则

- chip 数据 = 共享项（本机）+ 各长连接设备的可见共享项。**只读展示，不改共享项模型。**
- 段内顺序：目录在前、文件在后，同级按最近登记/最近访问倒序。
- 对端设备的可见性 = 现有广播范围（长连接设备自动获得全部共享项），不新增可见性概念。
- 拖出对端项：走 `drag.rs` 虚拟文件路径（起拖只取元数据，落盘时按需从对端拉流）。

## 8. 与现有实现的对齐

**可直接复用**

- 窗口锚定/尺寸切换：`planExpansion`/`orbSetRect`/`waitForViewport`/`orbScreenMetrics`（扩展一个 `planBloom`）
- 拖出：`drag.rs` + `dragStart`（本机 `CF_HDROP`、对端虚拟文件，均已实现并通过实机验证）
- 拖入：`onDragDropEvent`（`over`/`drop` 已监听，`App.svelte:1301`）
- 贴边/角标：`orbLayout.ts` 的 `planDock`/`spinForDock`/`isSliding`
- 动效降级：`MOTION`

**需要新增**

- `planBloom`：球屏rect + 盘半径 → 新窗口 rect（球心锚定 + 工作区 clamp）
- 盘的 DOM/样式（`.orb-bloom`、chip、分段色带）+ 极角命中
- `bloom` state 与 hover/drag-over 触发；窗口尺寸进出
- 拖入落点判定（决策 D）：`onDragDropEvent` 的 `position` → 判定弧段 → 推送该设备
- chip 的拖出触点：`dragStart` 需要一个"从球上起拖"的入口（当前只在面板内）

**成本 / 风险**

- 主要成本是 **bloom 的窗口尺寸往返**（hover 进/出各一次 `SetWindowPos`），有闪烁风险 → 复用现有视口等待补丁。
- 悬停展开会频繁改窗口尺寸；`prefers-reduced-motion` 下也照常改尺寸（动效可省、功能不可省）。
- 盘内极角命中需处理 DPI 缩放（统一用物理像素算，再转 CSS）。

## 12. 备选形态：卡片分页（用户提案，2026-09-20）

用户提案：球改为**圆角矩形卡片**，卡内 **2×2 = 4 个共享项**；右侧竖排**页码点**；
**一页 = 一台设备**（默认本机）；**滚轮翻页**（卡片切换动画）；**卡上方显示设备名，设备名可拖拽**。

### 12.1 评价：方向比环形盘更好

矩形卡片在"文件"这个场景上**优于**§4 的环形盘，理由：

- **名字离得开**：环形的 44px 片放不下文件名，卡片 2×2 的格子能放图标 + 截断名 —— 拖出前要认出是什么，这点是刚需。
- **命中无死区**：卡片是实心矩形，环形盘四角 + 片间缝都是透明死区。
- **翻页心智成熟**：分页点 + 滚轮是通用控件语汇，环形盘要现场学。

**结论：卡片分页作为主形态，§4 环形盘降为备选。** §2 决策 A（只有条目是拖出源、其它区域是移窗）保持不变，但实现从"极角命中"简化为"格子命中"。

### 12.2 需要补的规则（提案里缺的）

| 缺口 | 建议 |
|---|---|
| 4 格放不下怎么办 | 卡 = **快捷区**、面板 = **全量管理**；段内 >4 时第 4 格变 `+N`（点击定位到面板该来源标签）。**明确卡不追求全量** |
| 哪 4 项 | 规则：目录优先、组内最近登记/访问倒序（与 §7 一致）；是否支持钉住待定 |
| 翻页只靠滚轮 = O(n)、且不可见 | **点也可跳页**；hover 点显示设备名 tooltip；聚焦时 `←/→` 翻页 |
| 页码点只表示"第几页" | **点颜色 = 设备状态**（长连接=绿 / 已配对=蓝 / 未绑定=灰 / 离线=虚线），翻页前就能看出哪台有问题 |
| 哪些设备有页 | 只有**能看见其共享项**的设备才有页（= 长连接设备）；离线/未配对设备无页（其项对本机不可见）|
| 本机页为空 | 空态：卡内虚线框 + 「拖入文件或文件夹」；不自动跳到别的设备页（页码位置要稳定）|
| 状态栏 | header 除设备名外应带**该设备的状态点**与（长连接时的）链路指示，与 §3.1 F-94 的状态框区分开 |
| 常显 vs 悬停展开 | **常显卡片违背 N-04 与"悬浮球"身份**（一块 200px+ 的置顶矩形会挡住下层应用的点击/滚动）。建议：**收起态 = 现有 62px 球，悬停/拖拽接近 → 展开成卡片**，或提供"常显/自动收起"开关 |

### 12.3 手势（与决策 A 合并后）

**只有 4 个内容格是拖出源；header、页码点、卡内空白全部 = 移窗/点击。**
于是"设备名可拖拽"正好落在**标题栏 = 移窗手柄**这个桌面惯用法上 —— 它同时回答了原方案里
"拖动悬浮球怎么设计"的顾虑：**移窗不再和拖出抢手势**（详见 §5）。

| 指针动作 | 命中 | 结果 |
|---|---|---|
| 单击 | 内容格 | 展开面板并定位到该项 |
| 拖动 | 内容格 | 原生拖出（OLE，复用 `drag.rs`）|
| 拖动 | header / 页码点 / 空白 | **移动窗口** |
| 滚轮 | 卡内任意处 | 换页（换设备）；到边界不循环 |
| 单击 | 页码点 | 跳到该页 |
| 外部文件拖入 | 卡内 | 高亮 → 落下 = 登记共享项（决策 D 是否按页区分推送，待定）；**同一条路径是幂等的** —— 不新增、不改名、不重置广播开关（F-21 去重）|

> 2026-09-21：内容格的**单击**语义已改 —— 单击不做事，**双击**才是"进入/打开"，并新增了
> 「钻入子目录 + 返回上一层」。以 §13 的手势一节为准。

### 12.4 成本/风险（相对现有代码）

- 卡尺寸 ≈ 220×150（CSS px）+ 右侧点列；窗口需从 90×90 长到 ~270×190 → 复用 `planExpansion`/`waitForViewport`。
- 常显模式对 N-04（内存 <100MB、CPU 近 0）影响不大，但对**屏幕占用/点击遮挡**影响大 → 建议默认悬停展开。
- 拖出复用 `drag.rs`，无新增后端；新增前端：卡结构、翻页状态、格子命中、页码点状态色。
- 翻页动画沿用 `MOTION`（`prefers-reduced-motion` 归零）；用 transform/opacity，避免布局抖动。

**与 §12 提案的差异**（以原型为准）

1. 卡内不是 2×2 四格 + `+N`，而是**两列 × 可视 2.5 行 + 卡内滚动**（原型如此）：滚轮先滚列表、
   到底/到顶继续滚才换页；`+N` 与"钉住"都没做。
2. **第一页永远是本机**（本机的共享项，与「本机」标签页同一份 `getShares()`；`isDir` 是后端
   问来的真元数据，不再按路径猜），其后每台长连接设备一页（它对本机可见的共享项 —— F-25 的
   广播范围，离线设备没有可列的东西）。本机页不看广播开关：那是给对端看的口径，这一页回答的是
   "我这台机器装了什么"。
3. **只有一页时不画右侧分页点**（没得翻），但那一列**位置照旧占着**：收起态是定尺（见 6.），
   窗口不会因为"这列画不画"而胀缩。（2026-09-21 改：原来只有一页时窗口从 236 收到 204 —— 一台
   设备接上/断开就让常驻桌面的东西自己变宽，比右边多一道透明空挡难看得多。）
4. 格子的第二行原型里是「23 项 / 4.2 MB」，现在真就是这两个数：目录给**直接**子项数
   （跳过 `.` 开头的项 —— 与展开该共享项看到的行数一致），文件给大小（`formatFileSize`）。
   两个数由后端问一次文件系统得来（本机 `ShareItemDto.isDir/size/itemCount`、对端 `/shares`
   同样三个字段），拿不到时是 `null`，界面退回「文件夹 / 文件」。
   **绝不用目录大小**：那要递归遍历整棵树，卡片是常驻悬浮态、一屏列 2–3 项，每次翻页都扫一遍
   不可接受（本机十来万文件量级就要秒级），也没有失效源（watcher 只盯共享项）。递归大小留给
   「右键属性」那种"点开了才拿"的入口。
   上一版这里显示的是共享项的**登记日期**（`MM-DD`）——连对端看到的都是"别人哪天加进来的"，
   纯噪声，已去掉。
5. 悬浮框**贴边收起**：卡片滑出屏幕，**被屏幕边裁掉**（2026-09-21 加，原为"只夹不吸附"）：
   窗口贴住工作区左/右边、悬浮框横向平移出窗口 —— **卡片整张在屏幕外，屏上只剩靠边那一条**。
   动画就是**卡片自己平移**：没有另一条"竖条"淡入淡出，所以露在屏内那一条的两个角是卡片自己的
   圆角（贴右 = 左上左下圆），另一侧是屏幕边切出来的直角（右上右下）。
   那一条里画的是 `.rq-dock`（在**每张卡里面**，`RectOrb.svelte`）：**两列** ——
   **图标 + 设备名同一列**（图标在这一列顶端）、`ip:port` 一列，都竖排：
   `writing-mode: vertical-rl` + **`text-orientation: sideways`**（默认的 `mixed` 只把拉丁字母转
   90°、汉字照旧正立，名字与 ip 会看起来两种朝向；`sideways` 让**所有字形一起转**）。
   横向锚在卡片贴边那一端（贴右从左边排起，贴左整块 `row-reverse` 镜像、图标落到右上角），
   贴左时两列文字再 `rotate(180deg)` —— 于是"右侧隐藏顺时针、左侧隐藏逆时针"；图标是标记，不转。
   露出的宽度是定数 **47**（`orbShape.RECT_DOCK_W` = 1 + 6 + 16 + 4 + 13 + 6 + 1，
   三条横向留白（内边距 6 / 列间距 4）都是收紧过的那一档）：
   竖排一列只占一个行高，与内容长短无关。
   **高度**才随内容变：`ip:port` 那一列可用满条高（16 字符竖排 94，IPv6 那种 39 字符封顶在
   132、省略号收尾）；**设备名那一列封顶 88 − 图标与名之间的间距**（当前间距 8 → 80）—— 它与图标同列、
   且在角标的横向范围之内：上限说的是"名字不越过下面那条角标带的上沿（卡片 y 111）"，
   而它从"y 9 + 图标 14 + 间距"起排，所以随着间距变大，这个封顶会自己变小。
   与圆球逐条同构：吸附阈值（20）/ 拖动期间"等松手"（`orb_mouse_down` 轮询）/ 只记左上角的
   幂等复原 / 悬停滑回（`--orb-inset`）/ 角标跟着贴边那一档走，**只有显示动效不同**：
   卡片滑出去的同时内容交叉淡入淡出（头与列表 ↔ 那两列）+ 角标放大一次（`rq-badge-tick`）。
   角标落位与圆球贴边后**逐项一致**（都落到贴边那一侧的对面）：贴右 → 左上是长连接设备数、
   左下是待处理通知数；贴左 → 右上是通知数、右下是设备数（对应圆球贴右的绿 10:30 / 黄 7:30、
   贴左的黄 1:30 / 绿 4:30）。**横向对齐**：角标里侧那条边落在 **ip 列的左缘**（贴左镜像）—— 这是不压到 ip 的极限，
   于是角标把"图标 + 设备名"那一列整个罩住（与卡片上"通知角标盖住 logo"同一读法）。
   横向锚点不换（黄只动 `left`、绿只动 `right`），否则四样位置里有一头是 `auto`，
   悬停滑回时角标只能"跳"不能"挪"。
   **悬停显示这一档带一道闩**（`App.setDockOrb` 的 `zoneHold`）：拖动落位那一刻指针本来就压在
   悬浮体上，照 `:hover` 直接显示的话"贴到边上"这一步看不到结果（那两列被滑回来的卡片盖着、
   卡片又与贴边前一模一样）。所以落位时先压住这一次显示，指针离开热区才解除，之后进出与圆球
   那套一致。圆球那一档仍走纯 `:hover`（滑出来的是同一颗球，指针在不在上面差别不大）。
   判吸附按**悬浮框**（卡片 + 右侧点列）的边缘算，不按卡片 —— 按卡片算的话贴右边时卡片离
   屏边还有 46px（点列 30 + 余量 16）就已经"贴到位"，复判一次会掉回未贴边，重启就丢形态。
   竖向不贴：卡片是横幅，贴上边露的是列表尾部、贴左边露的是分页点列，没有信息量。
   **已知代价**：窗口始终是整个 236×162（不能贴边时缩窗口 —— 悬停要在同一块窗口里把卡片滑回来），
   而贴边后屏上只看得见那 47px 一条，剩下那块透明区域照样吃点击（今天不贴边时也一样，
   只是"看不见还占着"的比例变大了）。
6. 尺寸**定尺**：卡片 176×134 + 右侧点列 20（间距 10）（原型值）+ 四处阴影/角标余量 = 窗口
   **236×162**（与 `lib.rs` 的 `collapsed_logical` 逐值一致）。**不随内容变**：点列画不画（见 3.）、
   卡片里 `ip:port` 有多长，都不改窗口宽度 —— 卡片头那行超宽时由 `.rq-ip` 自己省略。
   原型那套"按最长 IP 撑开"（`fitCardWidth` / `measureRectCardWidth`）2026-09-21 已撤掉：撑宽是
   随设备接入/断开发生的窗口重排，一件常驻物不该有这种抖动，而 IPv4 的 `ip:port` 本来就在 176
   的额度内（长成 IPv6 就省略号，认设备还有设备名那一行）。
7. 两枚角标与悬浮球**逐项对齐**（角位、颜色、含义都一致，见原型 2026-09-21 的改动）：
   左上＝待处理通知数（橙 `--notif`，0 时隐藏）、右上＝长连接设备数（绿 `--ok` 压暗）。
8. 右侧分页点列是**一条竖胶囊轨道**（`--surface` + 同描边 + 同 `--shadow`，上下半圆），
   高 = **卡片的 1/2**（`--rq-track-h: 67px`；垂直居中，刻意不跟卡片等高 —— 那是卡片旁边的
   一枚小指示器，等高会读成第二张卡），宽 = 列宽 20，与卡片隔 10px。点在上面；两端各 8px
   （`--rq-track-fade`）用一条 `--surface` 覆盖层**把点**渐隐 —— **渐隐的是点，不是胶囊**：
   胶囊本体是不透明白 + 描边 + 阴影，不能淡（淡了就不再是"与卡片同料"的那一枚，阴影也会断），
   这条覆盖层只是在本该实色的地方盖住点、再往中间淡出。必须柔化的原因：超出胶囊的点由
   `overflow: hidden` 裁掉，不柔化会在端头留下半颗被切开的圆点，读起来像渲染坏了。
   **静止不显示，hover / 键盘焦点进来才淡入**（`.rq:hover .rq-dots`、`.rq-dots:has(.rq-dot:focus-visible)`）：
   悬浮框是桌面常驻物，而这枚胶囊是第二件有实体、有阴影的东西；点只在表达"你在第几页"，
   而"一共几台设备"由右上角那颗绿角标常显。隐藏时 `pointer-events: none`（否则点在没有东西
   的透明窗口上会把页码点跳），触发面是整个 `.rq`（卡片 + 间距 + 点列那 30px），这样指针从
   卡片移到点上不会把它闪没。焦点必须用 **`:focus-visible`** 而不是 `:focus-within`：鼠标在
   button 上按下时 Chromium 会给它焦点，用后者的话点过一次分页点、胶囊就永远挂着。
   空间照常占着（窗口尺寸不变，没有重排）。
   颜色**不带色相**：当前页 = 1.5× 实心 `--fg`，其余 = `--fg` 26% 再乘原型那条"越远越淡"的梯度。
   为什么要有轨道：这一列是全应用**唯一没有底衬**的东西 —— 它贴在卡片右边、直接画在桌面上，
   于是深灰点落在深色壁纸上等于没有，主色蓝（原来的当前页色）落在黑壁纸上是一颗发光的蓝点。
   补上轨道后任何壁纸下都等同于"白底那一档"；蓝一并去掉（卡上已有黄/橙/绿三支彩色，且蓝是
   唯一的冷色、也是唯一没有含义的一支）。
   代价是窗口余量（只有右侧一笔）：轨道自己也要投 `--shadow`，实测它右缘可见半径 13~14px，
   而"间距 + 点列"那 30px 已经吃不下它，所以 `RECT_SLACK.right` 6 → 16（定尺之后只剩这一档）；
   底部**不用动** —— 轨道矮了，它下缘的阴影落在卡片下沿以上，比卡片自己的 17px 近。
   窗口因此是 **236×162**（`orbShape.ts` 与 `lib.rs` 的 `collapsed_logical` 同步）。
   少一像素，阴影会被窗口边硬裁成一条切线。

9. 卡片左上角是**一格常驻位**：没通知时是项目 logo（`Logo.svelte`，与球的球心、面板左上角同一枚），
   有通知时让位给左上那颗角标 —— 角标落点（`top/left: -5px`）正是设备名行左边那段让位区，
   一出现就**整个盖住** logo。**这是刻意的，不是"被遮住的 bug"**。
   唯一约束是"角标下缘一丝不露"：行盒（本机 176 宽那档实测 y 9–24.2、高 15.2）比角标矩形
   （y −5–23）低，所以 logo 取 **12px 再上提 1px**（12px 直接居中时右下角会切进角标右下圆弧
   0.06px）。已验证：角标显示时 logo 四角**全部**落在角标轮廓（含 12px 圆角）内，两档都不与
   设备名重叠（名字仍从 x 37.67 起）。

10. 头部第二行：`ip:port` 在左、**项数贴卡片右内边距**（`.rq-headmeta` 的
    `justify-content: space-between`，最小间隔 6px）。原型同步改了（2026-09-21）。定尺之后头部
    右侧本来就有余量，项数挂在 IP 屁股后面会读成"和 ip 连在一起"。它贴的是**头部那行**的右端
    （头部自己有 `padding: 0 2px`，与原型一致 —— 比列表右端内 2px）。
IP 顶住时仍是**它**先省略号收尾（`.rq-ip` 的 `max-width`/`text-overflow`），项数不让位 ——
   "23 项" 被截成 "2…" 比 IP 被截还难读。

11. **参考点统一为悬浮体左上角**（2026-09-21 修）：展开方向判定、展开窗口落位、收起落位、位置记录
    全部只看**悬浮体（球 / 卡片）在屏幕上的左上角**，不看 OS 窗口的矩形。窗口 = 悬浮体 + 四周
    阴影/角标余量，两种形态的窗口尺寸与内缩都不同（圆球 90×90 内缩 14；悬浮框 236×162 内缩 14/10），
    拿窗口算的后果：同一个悬浮体位置展开出来的面板，两种形态差整整 146px（236 − 90），
    而且面板开着改形态再收起时悬浮体还会跳 4px（上下内缩的差）。
    `planExpansion` 只吃一个点，面板贴着它展开（朝右 = `[点, 点+宽]`、朝左 = `[点−宽, 点]`）——
    面板会盖住悬浮体自己那一块，但展开态悬浮体本来就不画。收起用 `planCollapse` 把这个点按面板位移
    平移回去，再按**当前形态**反推折叠态窗口（`App.svelte` 的 `windowFromBody`）交给贴边判定。
    参考点取**此刻的实际位置**（窗口左上角 + `--orb-x/y`，贴边那一档的偏移也在里面），
    于是贴边展开时面板正好贴着露在屏内那一条。残余差异只有贴边那一档：露出的竖条本身宽
    21（圆球 1/3）与 47（卡片）不同，面板跟着差这 26px —— 这是两档贴边几何自己定的，不是错位。

**手势（2026-09-21 改：单击不再有"跳标签页"，双击才有动作）**
- **内容格**：拖动 = 拖出源（复用 `drag.rs` 的 OLE 拖出：本机项 `CF_HDROP`、对端项虚拟文件）；
  **双击** = 目录**钻进去**（整张列表换成那一层的内容）、文件**用系统默认程序打开**
  （本机项开原文件，对端项按 S-02 先落一份副本再打开）；**单击不做事**。
- **列表头那格「↰ 上一级」**（只有钻进去才在）：**双击**回上一层 —— 子目录 → 父目录 →
  共享项根 → 共享项清单；按 `Esc` 同效。它不参与移窗、也不是拖出源。
- **header / 分页点 / 卡内空白**：移窗（越 4px 阈值才交给 OS 拖窗口），否则松手当单击 =
  展开/收起面板。分页点单击 = 跳页。
- 滚轮 = 先滚列表再翻页；卡内 `←/→`、`Home/End` 与方向键同样翻页。
- 翻页动画逐值照原型（400ms「抽出 / 被扫过」、角标呼吸 280ms、分页点梯度与居中平移），
  `prefers-reduced-motion` 下整条归零。

**为什么"返回上一层"是列表里的一格而不是别的**（2026-09-21）：双击一个目录就是"进去"，
返回就是**双击一个叫「上一级」的目录** —— 同一个手势的正反面，不用学第二套；也不需要新增
常显控件（右侧那 30px 列保持"静止时透明"的克制），代价只在钻进去时付出（占一格）。备选是
「双击 header 回上层」（零格成本，但与"单击 header = 展开面板"打架）与「右侧常显一枚 ↰」

**起拖的两处稳健性**（2026-09-21，用户报"不在焦点状态下第一次拖拽没有用"）：
1. **拖出要先抓指针捕获**（`dragOut` 动作）：拖出的判定靠这一格自己的 `pointermove`，而事件
   只送给"指针底下那个元素" —— 甩得快时第一个 move 已经落在格子之外，那一趟事件谁都没收到，
   **整次拖出不成立**（用户看到的正是"拖一下没反应，再慢慢拖一次就行"）。捕获之后 move 一律
   先送到起手那一格；交给 OS 之前再放掉（理由见下面那条）。
2. **起拖前先把窗口带到前台**（`orb_window::ensure_foreground`，两条路都调）：OS 的窗口模态
   移动循环与 OLE 的 `DoDragDrop` 都只在窗口是前台窗口时才真正吃住指针，而"点击激活"是异步的
   —— 指针动得快时，起拖请求可能赶在激活落地之前交出去，那一次就安静地不成立。点击本来就会
   把窗口带到前台，这一步只是把它**提前**，不改变用户能观察到的东西。

**指针捕获必须在交给 OS 的那一刻放掉**（`RectOrb` 与 `Orb` 两处同样处理）：按下时抓捕获是为了
"阈值判定期间指针移出小部件也还能收到 move"，而 `start_dragging` 之后页面再也收不到
`pointerup`，捕获就没法在 `onPointerUp` 里释放 —— **留着的捕获 = 留着的 `:hover`**（Chromium
把捕获目标当作"指针悬停在它上面"），于是 hover 出来的分页点胶囊、贴边球的滑出态都会一直挂着，
指针移开也不消失（实测：指针离 400px 后 `.rq:hover` 仍为真）。
