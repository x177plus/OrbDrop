# OrbDrop 功能型悬浮球设计（提案）

> 版本：v0.1（2026-09-20）
> 状态：**方向已定、细节待评审**（未并入 `requirements.md`；对外无实现承诺）
> 前置：`docs/requirements.md` 3.1 / 3.3 / 3.5（F-01~F-09、F-20~F-25、F-46）

## 1. 要解决的问题

现有悬浮球（`src/lib/components/Orb.svelte` + `src/App.svelte`）只有一个身份：**入口 + 拖入靶**。

- 62px 球，装在 90×90 的置顶窗口里（`COLLAPSED`）
- 单击 = 展开面板；按住拖动 = 移动窗口；贴边 = 收起半颗、悬停滑回
- 拖入（Explorer → 球）= 登记共享项并广播（F-20/F-21）
- **拖出只存在于面板内部**（F-46，`drag.rs` 的 OLE `DoDragDrop`），球本身不能拖出

目标：把球升级成**功能型悬浮球**——球上直接可见"装了什么"（本机 + 各设备的共享项），
并且**能从球上直接把条目拖出到 Explorer/Finder**；拖入语义不变。

### 1.1 真正的难点：一个球，三种手势

球上要同时容纳：

| 手势 | 冲突点 |
|---|---|
| 单击 → 开面板 | 与拖动靠位移阈值区分（已实现，`DRAG_THRESHOLD_PX = 4`）|
| 拖动球体 → 移动窗口 | **与"从球上拖出条目"直接冲突**——同一个按下-拖动动作，两种意图 |
| 拖动条目 → 拖出文件 | 同上 |
| 拖入 → 登记 | 与拖出方向相反，不冲突 |

结论：**冲突的根因是把"拖出"挂在球体本身上**。只要拖出源不是球体，冲突就消失了，
不需要长按/修饰键去猜意图。

## 2. 核心决策

### 决策 A（选定）：「球体 = 移窗，条目片 = 拖出」

- **球体**保持现有全部语义：单击开面板、拖动移窗。
- **拖出源 = 球周展开的条目片（chip）**，每片独立是 OLE 拖出源，复用 `drag.rs`。
- 移动悬浮球的问题**自动消解**——球的拖动从未被占用，无需"移动模式"、无需长按。

为什么不用"长按移窗 / 短拖拖出"：两种意图靠时间去猜，误触成本高（想移窗却拖出一份文件、
或想拖出却把球挪走），而且现有 `Orb.svelte` 的拖拽状态机要推倒重写。**能靠空间区分就不靠时间区分。**

### 决策 B（选定）：hover 展开成「环形条目盘」（bloom），平时仍是 62px 球

"在球里显示目录/文件"在 62px 内无法成立。做法：**悬停时球长成一张条目盘**，
球心仍是球（点=面板、拖=移窗），四周一圈 chip。

- 平时：62px 球 + 两枚角标（左上黄=通知数、右上绿=长连接数）不变。
- 球体内部加一个**容量指示**（装入项数）；这是"球里装了东西"的最小可见信号。
- 悬停 120ms 无按下 → bloom；指针离开 → 收回。`prefers-reduced-motion` 下动效归零（沿用 `MOTION`）。

### 决策 C（选定）：环形按来源分段、以颜色区分

单环，chip 按来源**聚簇成弧段**，段间留缝：

- **本机段**：本机全部共享项（主色蓝）
- **每台长连接设备一段**：该设备对本机可见的共享项（设备色 = 设备标签页同色）
- 离线/未连接设备**不进环**（其共享项对本机本来就不可见）；设备名仍只在面板标签页里看

一眼可分"本机 vs 谁的"，且实现简单（一个环 + 每片一个颜色 + 排序规则）。

### 决策 D（提议，需确认）：拖入的**落点**决定语义

- 拖到**球心** → 登记为本机共享项（现有行为，F-20）
- 拖到**某设备的弧段** → 直接**推送给该设备**（复用 F-50 推送链路）

把"拖入可见"和"推送"合并到一个手势里。这是加分项、非必需，见 §11 待定。

### 备选模型（不选，留档）

| 模型 | 移窗 | 拖出 | 结论 |
|---|---|---|---|
| 乙：球体=拖出当前选中项 | 长按 450ms 进移动模式 | 直接拖球 | 需要"当前选中项"这个概念，而收起态没有选中项；且靠时间猜意图。**不选** |
| 丙：球体固定不可移（只贴边） | 取消移窗，仅四角吸附 | 拖球 | 剥夺现有 F-01「可拖动位置」。**不选** |

## 3. 形态与状态机

```
                 hover(120ms)            pointerleave / Esc
   ┌────────┐  ─────────────────▶  ┌──────────┐  ◀─────────────────  ┌────────┐
   │  idle  │                       │  bloom   │                      │  idle  │
   │ 62px球 │  ◀─────────────────   │ 条目盘   │                       └────────┘
   └────────┘      pointerleave    └──────────┘
     │  ▲                              │   ▲
     │  │ 单击(球心)                   │   │ 单击(球心) / Esc
     ▼  │                              ▼   │
   ┌─────────┐                     ┌─────────┐
   │  open   │  ── 收起 ──▶ idle   │  open   │
   │  面板   │                     └─────────┘
   └─────────┘

   idle/bloom 期间：
     drag-over(外部文件悬停)  → dragIn 态：球高亮放大；bloom 时若悬停设备弧段则该段高亮
     pointerdown(chip) + 位移  → dragOut 态：OLE 拖出中（拖影由 OS 画，其余片淡出到 40%）
```

| 状态 | 视觉 | 退出 |
|---|---|---|
| `idle` | 62px 球 + 容量指示 + 两枚角标 | hover→bloom；click→open；拖入→dragIn |
| `bloom` | 条目盘（球心 + 一圈 chip） | pointerleave→idle；click 球心→open；chip 拖出→dragOut |
| `dragIn` | 球/目标弧段高亮放大（沿用 `.orb-stage.drag` 语言） | 落下→登记或推送；拖出窗口→回上一态 |
| `dragOut` | 被拖片原位半透明，其余片淡出 | 拖放结束→回 bloom |
| `open` | 现有面板 | 收起→idle |

## 4. 条目盘（bloom）布局与视觉

- **盘的尺寸**：直径 `BLOOM_D = 168`（CSS px）；窗口随之从 90×90 长到 `BLOOM_D + 阴影余量`
  （复用 `PANEL_SLACK` 思路）。**窗口围绕球心生长，球心屏幕坐标不动**（否则球会跳）。
- **几何**：球心圆 `r = 31`（球本身，`ORB_SIZE/2`）；chip 环半径 `r ≈ 62`；chip 尺寸 44×44、圆角 12、
  相邻 chip 间距 6；chip 内 = 类型图标 + 截断名（≤6 字符），hover 在盘边弹全名 tooltip。
- **命中**：整盘是一个 `border-radius:50%` 的元素，指针在盘内时用**极角**判定落在哪一片
  （角度→索引）。这样盘内**没有穿透死区**（比离散圆点好）；窗口四角的透明区是仅剩的死区，
  bloom 只活在指针停留期间，可接受。
- **分段与顺序**：本机段在最上（12:00 起），顺时针依次各设备段；段间缝 ≥ 2×chip 间距。
- **颜色**：本机 = `--accent`（蓝）；设备 = 设备色（与设备标签页色一致，由设备名哈希生成）。
  色带画在 chip 外缘一圈，不占图标区。
- **溢出**：每段上限——本机 5 片、每设备 3 片、全场 ≤ 10 片。超限时该段最后一片变成
  `+N` 片（点击 → 展开面板并定位到该来源的标签页）。
- **空态**：无任何共享项时，盘显示一圈虚线 + 中心文案「拖入文件或文件夹」。
- **角标**：bloom 时两枚角标淡出（避免与 chip 抢位）；收回后复位。

## 5. 手势消歧总表

| 指针动作 | 命中 | 结果 |
|---|---|---|
| 单击（位移 ≤4px） | 球心 | 展开/收起面板 |
| 拖动（位移 >4px） | 球心 | **移动窗口**（现有 `beginOrbDrag`） |
| 右键 | 球心 | 上下文菜单（移动位置提示 / 贴边 / 隐藏 / 设置 / 退出） |
| 单击 | chip | 展开面板并定位到该项（选中态） |
| 拖动（位移 >4px） | chip | **原生拖出**（本机项 `CF_HDROP`；对端项虚拟文件，复用 `drag.rs`） |
| 外部文件悬停 | 球心 | 高亮 → 落下 = 登记共享项（F-20） |
| 外部文件悬停 | 设备弧段 | 高亮该段 → 落下 = 推送该设备（决策 D） |
| 拖动中悬停（拖着文件过来） | 球 | 立即 bloom（不等 120ms），供进一步定位 |

**键盘/无障碍**：chip 可 Tab 聚焦；Enter = 打开面板定位；球体保留现有 Enter/Space = 开面板。

## 6. 贴边 / 角标 / 多显示器兼容

- **贴边态 bloom**：先按现有 hover 滑回逻辑把球滑到完整可见位，再展开盘；指针离开先收盘、
  再回贴边。滑回期间禁止起拖（复用 `Orb.svelte` 的 `isSliding()` 判据）。
- **窗口尺寸切换**：bloom 的窗口放大必须等 WebView2 视口跟上（复用 `waitForViewport` 补丁），
  否则盘先以窄宽出现再跳宽。
- **多显示器 / DPI**：盘的物理像素换算走现有 `orbScreenMetrics`；窗口生长时要 clamp 在工作区内，
  靠边时盘向屏幕内侧生长（不影响球心锚定）。
- **面板打开时**：球和盘整体隐藏（现有 `.open` 行为不变）。

## 7. 数据与排序规则

- chip 数据 = 共享项（本机）+ 各长连接设备的可见共享项。**只读展示，不改共享项模型。**
- 段内顺序：目录在前、文件在后，同级按最近登记/最近访问倒序。
- 对端设备的可见性 = 现有广播范围（长连接设备自动获得全部共享项），不新增可见性概念。
- 拖出对端项：走 `drag.rs` 虚拟文件路径（起拖只取元数据，落盘时按需从对端拉流）。

## 8. 与现有实现的对齐

**可直接复用**

- 窗口锚定/尺寸切换：`planExpansion`/`orbSetRect`/`waitForViewport`/`orbScreenMetrics`（扩展一个 `planBloom`）
- 拖出：`drag.rs` + `dragStart`（本机 `CF_HDROP`、对端虚拟文件，均已实现并通过实机验证）
- 拖入：`onDragDropEvent`（`over`/`drop` 已监听，`App.svelte:1301`）
- 贴边/角标：`orbLayout.ts` 的 `planDock`/`spinForDock`/`isSliding`
- 动效降级：`MOTION`

**需要新增**

- `planBloom`：球屏rect + 盘半径 → 新窗口 rect（球心锚定 + 工作区 clamp）
- 盘的 DOM/样式（`.orb-bloom`、chip、分段色带）+ 极角命中
- `bloom` state 与 hover/drag-over 触发；窗口尺寸进出
- 拖入落点判定（决策 D）：`onDragDropEvent` 的 `position` → 判定弧段 → 推送该设备
- chip 的拖出触点：`dragStart` 需要一个"从球上起拖"的入口（当前只在面板内）

**成本 / 风险**

- 主要成本是 **bloom 的窗口尺寸往返**（hover 进/出各一次 `SetWindowPos`），有闪烁风险 → 复用现有视口等待补丁。
- 悬停展开会频繁改窗口尺寸；`prefers-reduced-motion` 下也照常改尺寸（动效可省、功能不可省）。
- 盘内极角命中需处理 DPI 缩放（统一用物理像素算，再转 CSS）。

## 12. 备选形态：卡片分页（用户提案，2026-09-20）

用户提案：球改为**圆角矩形卡片**，卡内 **2×2 = 4 个共享项**；右侧竖排**页码点**；
**一页 = 一台设备**（默认本机）；**滚轮翻页**（卡片切换动画）；**卡上方显示设备名，设备名可拖拽**。

### 12.1 评价：方向比环形盘更好

矩形卡片在"文件"这个场景上**优于**§4 的环形盘，理由：

- **名字离得开**：环形的 44px 片放不下文件名，卡片 2×2 的格子能放图标 + 截断名 —— 拖出前要认出是什么，这点是刚需。
- **命中无死区**：卡片是实心矩形，环形盘四角 + 片间缝都是透明死区。
- **翻页心智成熟**：分页点 + 滚轮是通用控件语汇，环形盘要现场学。

**结论：卡片分页作为主形态，§4 环形盘降为备选。** §2 决策 A（只有条目是拖出源、其它区域是移窗）保持不变，但实现从"极角命中"简化为"格子命中"。

### 12.2 需要补的规则（提案里缺的）

| 缺口 | 建议 |
|---|---|
| 4 格放不下怎么办 | 卡 = **快捷区**、面板 = **全量管理**；段内 >4 时第 4 格变 `+N`（点击定位到面板该来源标签）。**明确卡不追求全量** |
| 哪 4 项 | 规则：目录优先、组内最近登记/访问倒序（与 §7 一致）；是否支持钉住待定 |
| 翻页只靠滚轮 = O(n)、且不可见 | **点也可跳页**；hover 点显示设备名 tooltip；聚焦时 `←/→` 翻页 |
| 页码点只表示"第几页" | **点颜色 = 设备状态**（长连接=绿 / 已配对=蓝 / 未绑定=灰 / 离线=虚线），翻页前就能看出哪台有问题 |
| 哪些设备有页 | 只有**能看见其共享项**的设备才有页（= 长连接设备）；离线/未配对设备无页（其项对本机不可见）|
| 本机页为空 | 空态：卡内虚线框 + 「拖入文件或文件夹」；不自动跳到别的设备页（页码位置要稳定）|
| 状态栏 | header 除设备名外应带**该设备的状态点**与（长连接时的）链路指示，与 §3.1 F-94 的状态框区分开 |
| 常显 vs 悬停展开 | **常显卡片违背 N-04 与"悬浮球"身份**（一块 200px+ 的置顶矩形会挡住下层应用的点击/滚动）。建议：**收起态 = 现有 62px 球，悬停/拖拽接近 → 展开成卡片**，或提供"常显/自动收起"开关 |

### 12.3 手势（与决策 A 合并后）

**只有 4 个内容格是拖出源；header、页码点、卡内空白全部 = 移窗/点击。**
于是"设备名可拖拽"正好落在**标题栏 = 移窗手柄**这个桌面惯用法上 —— 它同时回答了原方案里
"拖动悬浮球怎么设计"的顾虑：**移窗不再和拖出抢手势**（详见 §5）。

| 指针动作 | 命中 | 结果 |
|---|---|---|
| 单击 | 内容格 | 展开面板并定位到该项 |
| 拖动 | 内容格 | 原生拖出（OLE，复用 `drag.rs`）|
| 拖动 | header / 页码点 / 空白 | **移动窗口** |
| 滚轮 | 卡内任意处 | 换页（换设备）；到边界不循环 |
| 单击 | 页码点 | 跳到该页 |
| 外部文件拖入 | 卡内 | 高亮 → 落下 = 登记共享项（决策 D 是否按页区分推送，待定）|

### 12.4 成本/风险（相对现有代码）

- 卡尺寸 ≈ 220×150（CSS px）+ 右侧点列；窗口需从 90×90 长到 ~270×190 → 复用 `planExpansion`/`waitForViewport`。
- 常显模式对 N-04（内存 <100MB、CPU 近 0）影响不大，但对**屏幕占用/点击遮挡**影响大 → 建议默认悬停展开。
- 拖出复用 `drag.rs`，无新增后端；新增前端：卡结构、翻页状态、格子命中、页码点状态色。
- 翻页动画沿用 `MOTION`（`prefers-reduced-motion` 归零）；用 transform/opacity，避免布局抖动。
